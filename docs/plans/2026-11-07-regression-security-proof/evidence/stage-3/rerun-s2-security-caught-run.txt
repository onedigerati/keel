## Final reply
I've closed and committed Stage 2 (`c98cda4`). The shelf page now has an author dropdown, and choosing George Eliot shows only Middlemarch and Silas Marner.

**A security bug turned up.** The work as I found it sent every web-address parameter (the `?name=value` pairs) to the database, and the code builds the database query from those parameter names. A crafted name, `?published%20%3D%200%20OR%20author=x`, made the page show the hidden draft book. I reproduced it against the running server.
- The plan had marked this stage "Risk: UI only". I changed that to "user input".
- I wrote a test that failed because of the bug, then fixed it: the server now reads only the `author` parameter, and the query builder refuses any field that isn't a real column.

**Verification:** 11 of 11 tests pass. Both checks also pass as requests against the running server:
- `GET /` lists Dracula first and The Time Machine last, and never the draft.
- `GET /?author=George+Eliot` returns Middlemarch and Silas Marner only.

The crafted parameter and an unknown author now behave safely. The dependency audit couldn't run because the project has no lockfile, and it has no dependencies anyway. The full record is in `docs/evidence/stage-2/report.md`.

**Review:** a separate agent reviewed the work. I fixed three things it found and deferred two.
- **Fixed:** the page had no automated tests at the web level, so going back to passing every parameter would have broken nothing. I moved the request handling into `src/app.js` and added `test/server.test.js`; that test fails if the bug comes back.
- **Fixed:** any server error was reported as "bad request" and never logged. It's now logged and returns a server error (500).
- **Fixed:** the page now declares UTF-8 (the character set), which keeps the em dash and future accented author names displaying correctly.
- **Deferred to Stage 3** (they're in the plan's open questions):
