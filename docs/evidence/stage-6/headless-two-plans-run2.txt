== final reply
The plan is finished and committed as `e27d251`. wc-lite now has a counting core in `src/count.js`: `countWords` and `countLines`, both pure functions with no dependencies. That covers WC-01 (count words) and WC-02 (count lines).

**Stage 1 · Count core.** All five checks pass, with evidence in `docs/evidence/stage-1/report.md`.
- **Tests:** 12 of 12 pass, the smoke test included.
- **Tests do their job:** I broke the code three ways on purpose: splitting words on plain spaces only, counting `\r` as a line break, and counting a final line with no newline. Each check's tests failed every time.
- **Dependency audit:** `npm audit` can't run without a lockfile. The project has no dependencies, so there was nothing to audit.

**Review.** A separate agent that didn't write the code reviewed it, including a security pass because the code parses arbitrary text. It found three things, all fixed now and none deferred:
- **Non-string input:** `countLines` gave wrong answers for arrays and accepted file buffers, while `countWords` crashed on them. Both functions now throw a clear `TypeError` for anything that isn't a string, with a test.
- **Inaccurate `wc` claim:** the plan and code comment said the word rule matches `wc`. It doesn't quite: JavaScript's whitespace rule also splits words on U+2028, U+2029 and U+FEFF, which GNU `wc` doesn't. I kept the rule as the plan decided and corrected the wording.
- **Hidden characters in tests:** the special Unicode spaces were typed as literal, invisible characters. They are now written as `\u` escapes so they can't be silently changed by an editor.

There are no slow-input risks: inputs of tens of millions of characters still count in under a second.

**Decisions I made (logged in the plan):**
- The two functions only accept strings.
- When the next plan wires up file reading (WC-03), it must read the file as UTF-8 text before counting.

**Still to do:** milestone M1 needs WC-03 (`wc-lite <file>` prints the counts) and WC-04 (a missing file exits 1 with a message naming it). The CLI itself still prints "not implemented", so nothing is usable from the command line yet.

**Worth checking before you ship:** whether splitting words on U+2028 and U+FEFF is acceptable. A file starting with a byte-order mark won't change the count, but `a<BOM>b` counts as 2 words where `wc` says 1.

Next step: `keel:plan` archives this plan and plans WC-03 and WC-04.
