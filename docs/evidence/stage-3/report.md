## History
- 2026-11-08 · Review found project rules matched too narrowly (`make -j4 release`, path forms, plurals), ordinary Markdown formatting dropped rules silently, every Bash call in every project read `CLAUDE.md`, rules were read twice per call, the agent could delete a rule mid-run, and a stat-then-read race. Its security pass also found the built-in outward check missed `{ git push; }`, `if …; then git push`, `sudo -u x git push`, `timeout 60 git push` and `bash -c "git push"` (pre-existing). Fixed: wider matching, Markdown-tolerant rules, gated and single reads, session-sticky rules, read from the resolved path, and a parser that looks through grammar, wrappers and shell strings.
- 2026-11-08 · A fresh re-review of the rewritten parser found pushes still hidden behind a commit message with `:(` in `$(…)`, a backslash line break, `<(…)`, a stdin-fed shell, an unquoted heredoc, `find -exec`, run-time-built commands and npm option values; no false holds on ~85 everyday commands. Fixed with a quote- and heredoc-aware scan; the remaining limits are in the README (scope: a guardrail against mistakes, not a sandbox).
