## History
- 2026-11-09 · First pass: all checks passed as tested, but the live run showed a plan paused on an auth stage let a Write through. The correctness and security reviews found the same gap: `held()` required `Mode: autopilot`, so autopilot's own pause procedure switched the guard off. They also found the release wording ("a reply that starts with…") was looser than the rule, the paused path never named the reply, an approval in an unarmed session cleared nothing, a test that couldn't fail, and stale comments. Fixed: a paused risky stage is held while armed, exact wording everywhere, the paused rules and notice name the reply, approvals clear in unarmed sessions, the approve skill logs only when the hold lifted, more punctuation counts, and the vacuous test was replaced.
- 2026-11-09 · Second pass found the armed state is lost on `--resume` and `--fork-session`: a resumed process starts unarmed, so a paused risky plan isn't held there (lines 191–237 of [headless-paused.txt](headless-paused.txt)). It matches the standing rule that autopilot is armed per session; it's an open question in the plan.
